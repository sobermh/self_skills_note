# TokensCowork 插件开发

## 范围与现状确认

开发或编写用例前定位目标插件的独立仓库，读取 AGENTS.md、贡献规范、Git 状态和远程地址、包清单、锁文件、加载入口、运行时入口、测试与工作流。
确认实际包名、仓库身份和宿主依赖版本，不照搬示例插件的名称或兼容范围。

插件开发默认不修改产品总仓库；用户已明确授权更新外层时按其范围执行，源码子模块仍不直接修改。不擅自把市场插件改为内置插件或更新产品版本锁定。
保留已有改动。创建文件不等于获得提交、推送、发布、轮换凭据、重启用户应用或启用远程工作流的授权。

记录开始时的 HEAD、版本号和工作区差异。已知多个 Agent 共用仓库时，避免同时写同一文件；提交、改版本和创建发布标签由一个执行者负责。每次 Git 写入或发布前重新核对状态；出现其他执行者的新提交或差异，先确认内容与任务归属，不按旧快照覆盖、重做版本升级或移动标签。无法确认时只暂停有冲突的操作，继续不冲突的检查。

## 按任务读取规范

先确定任务模式和范围。开发、编写用例在目标插件的独立仓库完成；仅执行回归可从产品总仓库解析指定插件或全部固定插件，只读源码子模块。不因使用统一 Skill 自动进入所有模式。

- 功能开发或宿主升级适配：按改动读取下列规范，沿用现有测试并补充相关回归；兼容目标使用任务指定的真实依赖版本或固定提交，不硬编码某个 desktop/dsh 版本。
- 专门编写或完善用例：读取[功能回归规范](references/testing.md)的「编写与完善功能用例」，只修改指定插件；未指定时使用当前插件仓库。
- 仅执行回归：读取[功能回归规范](references/testing.md)的「仅执行功能回归」，按指定范围运行并报告。产品总仓库中未指定范围时执行全部具有标准入口的固定插件；当前独立插件仓库中未指定范围时只执行当前插件。不进入开发、补测试、打包或发布流程。
- CI 或发布：读取[发布要求](references/release.md)。明确要求发布时才进入实际发布流程；已有授权按范围执行，不重复确认。

- 新建插件或整理目录：读取[目录与模板](references/layout.md)。
- 宿主集成：读取[运行时契约](references/runtime.md)。
- 插件被产品内置且修改了宿主交互、文案函数或加载入口：同时只读核对外层构建适配与对应测试；修改外层需已有用户授权，源码子模块仍只读。
- 多语言文案：读取[目录与模板](references/layout.md)中的界面文案国际化要求；先确认界面是否真实存在，市场元数据双语则无条件要求。
- 仅修改元数据：只改元数据与对应测试；要求发布时再调整版本，不重写运行时代码。

## 实现与验证（开发及编写用例模式）

沿用插件已有的包管理器、框架和宿主 API。只添加实际需要的文件，不机械生成所有可选模板。
根目录 README.md 默认中文，英文补充文档放在 docs/。保留许可证和第三方归属声明。

**插件仓库必须有可跑的测试和一条标准命令**（`npm test` / `pnpm test` 之类，CI 与本地同一条）。遇到没有测试的仓库，先补最低限度的一组：加载入口可被 import、清单身份（包名、版本、仓库、`publishConfig.registry`）符合预期、声明了的运行时资源确实存在。**不要绕过它直接改代码**——没有测试的仓库里，任何"我改好了"都只是断言，而插件的失败面在宿主进程里，装上才发现等于用户先发现。补完再动功能。

已有测试的仓库沿用其框架，不另起一套；整理路径时同步修改所有执行入口和引用。用现有测试和相关构建检查验证变更。包内容变更需检查实际 tarball 文件列表与清单：
入口和加载补丁必须存在，必需运行时资源必须打包，凭据、本地会话、日志和测试产物不得打包。

功能回归默认使用 `test/test_cases.csv` 与 `test/run-test-cases.mjs` 两个文件：CSV 定义用例，执行脚本承载断言、夹具和固定上游信息；`test` 与 `test:cases`（按实际包管理器调用）共用入口。整理已有测试时保留有价值的断言并完成用例映射，再删除被替代文件，保持必要的进程隔离；有明确仓库约定时按其约定，不为了文件数量丢弃覆盖。

区分单元或 mock 断言、真实宿主集成、界面显示、安装升级和远程发布验证，不相互替代。
构建成功不代表宿主运行时兼容，代理返回文本成功不代表媒体渲染正常。

## 更新后的测试

每次插件更新完成后，运行一次该插件的标准功能回归入口 `test/run-test-cases.mjs`，优先使用仓库的 `npm run test:cases` / `pnpm run test:cases`。新增或改变行为时同步更新相关用例；失败或未完成时报告原因，修复后重新验证。不因提交、推送或发布再增加重复执行要求；已有 CI 检查按仓库约定执行。

外层超级项目的整体插件回归按需执行，由外层入口的开关变量控制，默认关闭；开启时按 product.json 固定的插件与上游版本逐个运行标准入口并汇总结果。沿用项目已有变量；没有时可采用 `TOKENS_COWORK_RUN_PLUGIN_TESTS=1` 作为开关约定，需要在外层脚本中实际接入才生效。整体回归不替代插件更新后的单插件测试，也不修改源码子模块。

## 交付

报告修改的文件与行为、实际执行的检查和剩余缺口。
发布时分别说明 Registry、准确版本、标签或提交、运行链接和已发布清单核验结果。
main 检查成功但跳过发布步骤，不是端到端发布成功。

本 Skill 提炼渐进式工具的通用经验，不要求其他插件实现工具发现、代理分发、工具分组或 token 基准测试。
